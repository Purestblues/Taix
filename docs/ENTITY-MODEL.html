应用实体模型

一页看懂：屏幕上的一段时间，怎么被认成「一个东西」。2026-11-11 定稿 · 未实现
3种实体：应用 / 网站 / 合并组
2套分类命名空间（互不相干）
1条守恒：总额两种视图都不变

01三个层次：数据不进实体层，视图不改数据

原始数据表

  • AppModels
    Name 是身份，File 是路径
  • AppSessions
    会话区间（UTC）
  • HoursLog / DailyLog
    应用 × 小时 / 天
  • WebSiteModels
    Domain 是身份
  • WebBrowseLogModels
    单次访问 + Duration
→

实体层（新增）

  • 应用实体 app:{ID}
  • 网站实体 site:{ID}
  • 合并组 grp:{ID}
  • 合并 = 视图期映射
    不写回任何表
→

视图

  • 统一实体表（默认）
    站点独立成行
  • 网站并入浏览器（开关）
    站点折回浏览器
  • 分类 / 应用 两种视图
合并组是可逆的映射层：拆开后成员自动回到自己的分类，因为它自身的 CategoryID 从来没被改过。

02核心难题：浏览器和网站是同一段时间的两次记录

Chrome 的 AppSessions60 分钟
chrome.exe
bilibili 的浏览记录40 分钟
bilibili.com
09:0010:00

直接相加会把这 40 分钟算两遍。今天靠「应用 / 网站」切换器回避矛盾；合成一张表就必须先扣减。

03扣减后：浏览器只剩余额，差额有名字

现状（未扣减）100 分钟
Chrome 60 分钟
bilibili 40（重复）
扣减后（统一实体表）60 分钟
bilibili 40
其他页面 20

新标签页、没收录的域名、扩展没上报的页面 → 一行「浏览器内其他页面」。它必须存在，否则那几分钟就从总额里凭空消失了。

05合并组：自动判定 + 可逆拆解

判定输入规则结果
Windows：exe 路径 + Publisher同目录同发布者 → 候选组主成员 = 组内时长最长者
组名可改，成员可拆
解散过的组不再重建
macOS：bundle id同 bundle 前缀 → 候选组
跨源（网页版 ↔ 客户端）仅手动绑定，不做语义猜测

分类：组跟母成员走，成员自己的分类一行不改 —— 拆分后它自动回到原分类，这就是「保留原有标签」在单值分类模型下的落地。

06验收线

不变式含义
守恒Σ 实体时长 = Σ 应用总时长，两种视图都成立
可逆合并 / 拆分 / 开关来十次，原始表一字未变
可下钻每一行都能点进详情；组合实体先列成员
身份不变改别名、改标题、换图标都不影响归属
差额可见为 0 隐藏，不为 0 必须有一行说明它是什么
