# v{version} 更新日志

> 接在 `fork.9`（子母程序合并）之后。这一版做 **N2 统一实体表的第一段**：
> 应用与网站不再各算各的，先扣成一张互斥的屏幕时间表，再出榜单。概览页已经换到这个口径。
> 另外补上了 `fork.9` 欠的两块地基：浏览器标识和发布者（Publisher）采集。

## 主要变化

- **统一实体表（概览页）**
  - 以前「应用榜」和「网站榜」是两张互不相干的表，同一分钟既算在被追踪的网站上、又算在浏览器里。
    现在服务端先把网站时长按浏览器会话区间扣掉，再出榜单：一行就是一段互不重叠的时间。
  - 浏览器行扣完剩下的部分独立成一行「**浏览器内其他页面**」（新标签页、未收录域名、扩展没上报的页面）。
    为 0 时隐藏；同时用多个浏览器时行名前缀浏览器名。
  - 两种视图总额一致：都等于「应用总时长」。切换视图只改变「浏览器那一段怎么分」，不制造也不吞掉时间。
  - 榜单行点进去仍然是原来的应用详情 / 网站详情；合并组的行悬停可以看到折进来的成员。

- **「网站并入浏览器」开关（概览页头部）**
  - 「独立显示」（默认）：网站各自成行，浏览器只显示其余额。右侧的网站列在这一档才有内容。
  - 「并入浏览器」：网站行消失，浏览器行拿回完整活跃时长，网站变成它下面的成员。
  - 开关状态存在配置里（`General.WebBrowserMerged`），下次启动保持。

- **浏览器标识：扩展上报时带上自己是谁**
  - 扩展本来就是按浏览器分别打包的（chrome / firefox / safari），现在构建时把浏览器名注入产物，
    每次上报带一个 `Browser` 字段。不靠运行期探测，零猜测。
  - 服务端 `WebBrowseLogModels` 新增 `BrowserRef` 列；历史记录保持 NULL，由「默认浏览器」兜底。
  - Chromium 系（Edge / Brave / Arc …）装的是 chrome 版扩展，上报的会是 `chrome`；服务端按「一族进程名」解析，
    同族里取时长最长的那个进程当实体。

- **发布者（Publisher）采集**
  - 监控进程新增读取文件版本资源里的 `CompanyName`，随上报一起送到服务端，落 `AppModels.Publisher`。
  - 它只用于「子母程序合并」的判定加固：同目录 + 同品牌的两条记录，如果都带发布者且发布者不同，就不合并
    （防止共用安装目录的不同厂商被并到一起）。历史数据没有发布者，按原来的路径规则走，行为不变。

- **子母程序合并搬到服务端 / 设置页**
  - 判定与组表进数据库（`EntityMergeGroups` / `EntityMergeMembers` / `EntitySuppressions`），
    自动组第一次被查询时落库，之后可以在设置页改名或解散；解散会记住「这组别再自动合并」。
  - 设置 → 常规 → 「子母程序合并」卡片现在读服务端，解散 / 恢复全部即时生效，本地 `app.merge.json` 不再使用。
  - 合并口径不变：安装目录锚点 + 进程名品牌；浏览器、系统目录、`setup` / `uninstall` 这类通用名不参与。

- **设置 → 常规：「默认浏览器」**
  - 列表来自浏览日志里出现过的浏览器，加上应用侧识别到的浏览器。
  - 第一项「自动推荐」= 不指定；选了之后，**没有浏览器标识的历史站点记录**统一归给它。
  - 这段历史完全由你决定归属，不会随「最近用了哪个浏览器」漂移。

- **配置版本 v5 → v6**（新增 `DefaultBrowser` 与 `WebBrowserMerged`），服务端会自动备份旧配置再升级。

## 升级注意事项

1. 首次启动会做三处数据库迁移（只加列 / 加表，不改历史数据）：`WebBrowseLogModels.BrowserRef`、
   `AppModels.Publisher`、三张合并组表。历史行全部留空，读取时按规则退化，不需要清库。
2. **浏览器插件需要重新安装一次**（用新版 `dist/chrome` / `dist/firefox` / `dist/safari`），
   旧版扩展不带上报里的浏览器标识 —— 不重装也能用，只是这些站点会按「默认浏览器」处理。
3. 在本版里，**只有概览页**换到了新口径。统计页、详细页、分类页、搜索结果、Web UI 仍然是旧的「应用表 / 网站表」，
   这期间的网站时长统计口径会与概览页略有差异，是刻意的分批（下一版统一切过去）。
4. 概览页的「分类 × 时段」柱图 / 占比图仍然用原来的分类矩阵（按分类聚合，不受应用与网站重叠影响），
   与榜单金额可能对不齐 —— 也留到下一版一起处理。
5. 浏览器日志是按小时桶存的，扣减的最细粒度是一小时的访问记录与会话区间的交集；
   极端情况下（跨小时的浏览记录）会有几分钟误差，差额行会把这些吸收进去。
