# v{version} 更新日志

> 接在 `fork.8`（视觉收尾 + 分类页卡片瘦身）之后。这一版**只动分类页的展示层**：
> 加了「紧凑 / 卡片」两种视图与排序菜单，数据结构、统计口径与 `fork.8` 完全一致。

## 主要变化

- **分类页：紧凑 / 卡片两种视图**
  - 标题栏右侧多了「视图」开关，默认「紧凑」：200×92 的扁卡，一屏 6 列、约 7 行
  - 「卡片」形态 168×148：图标 40px、时长用 20px 大字，适合分类不多、想看得更清楚的时候
  - 两种形态是**同一个控件的两套模板**，切换时不重建列表项——滚动位置和选中态都不会丢
  - 应用分类与网站分类共用这一份卡片控件（原来两处各写一遍）

- **分类页：排序菜单（时长 / 名称 / 数量）**
  - **时长**（默认）：今天用得多的排在前面，今天没用过的收在末尾按名称排
  - **名称**：按当前语言的字典序（中文即拼音顺序，`开发 < 科研 < 未分类 < 学习 < 娱乐`）
  - **数量**：应用数 / 站点数多的在前，空的分类收在末尾
  - 排序只是重排已经算好的卡片，**不重新请求数据**，切换是即时的；列表用 Move 重排，
    容器不重建，所以选中项与滚动位置同样保留
  - 选择会跟页面状态一起记住：进分类详情再返回，视图与排序都还在

## 修复

- **视图开关首次进入时一项都没选中**：`[PageState]` 只在「返回导航」时恢复状态，
  从侧边栏进分类页不会写入任何值，于是开关停在一个「什么都没选」的空态。
  现在视图与排序都有明确默认值（紧凑 / 时长）

## 升级注意事项

1. 本版不带数据结构变更，直接覆盖安装即可，历史数据不需要迁移。
2. 视图与排序的选择只在**返回上一页**时保留；从侧边栏重新进入会回到默认（紧凑 + 时长）。
   这是页面状态机制本来的行为，不是这一版引入的。
3. 主题色与明暗模式仍存在服务端配置里，升级后保持你原来的选择。

## 已知问题

- macOS 产物仍然只验证过「能构建 + 打包成功」，没有 Apple Silicon 机器实机跑过。
- 分类卡片是固定宽度（紧凑 200 / 卡片 168），列数不随窗口宽度变化；窗口很宽时右侧会留白。
- 空分类没有「折叠成一组」：现在只是稳定排在末尾、卡片上不画空的占比条。
  折叠需要把列表拆成两套集合并保证增删改同步，风险大于收益，留给 N5「分类 / 应用」视图一起做。
- 环形时钟中心时长（会话口径）与指标卡 / 柱图（小时桶口径）仍可能差几分钟，属历史口径差异，未强行统一。

## 工程侧

- 自动化测试 93 → **99** 例
  - 新增 4 例排序口径：0 时长（或 0 数量）稳定收尾、名称排序是纯字典序不被分组打断、
    数量降序、以及「只有时长没有数量」也算有数据（不能被当成空分类）
  - 新增 2 例就地重排：`Move` 不重建实例、已经有序时不产生任何集合变更
- `Librarys/CategoryCardStats` 新增 `CategorySortMode` / `Sort` / `ReorderInPlace`，
  排序口径全部落在纯函数里，不依赖界面状态
- 语言资源新增 `SortByDuration` / `SortByName` / `SortByCount` / `SortOrder` / `ViewMode`（中英各一份）
